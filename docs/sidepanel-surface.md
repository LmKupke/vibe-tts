# Side panel surface brief

## Scope and mode

The Chrome side panel is an **Operate** surface for controlling narration without losing visual orientation on the source page.

## User, job, and constraints

The user is reading or listening to a webpage and needs the primary playback action, current location, provider trust boundary, and recovery state to remain legible at narrow panel widths. The panel must be keyboard operable, remain useful with browser speech alone, and avoid implying that page content is local when an HTTP provider is active.

## Direction contract

**THESIS:** Treat narration as a live reading instrument: one unmistakable transport surface, one continuous progress rail, and a compact transcript cue. Refuse the category default of a settings dashboard made from unrelated cards.

**OWN-WORLD:** A quiet ink-and-cobalt operating surface with chalk-white fields, crisp one-pixel rules, squared controls, and a single vermilion live marker. Text hierarchy comes from scale, weight, and alignment rather than decorative containers.

**STORY:** The user sees whether this page is ready, presses one dominant play control, watches the active sentence cue and progress advance, then adjusts only the few properties that affect listening. Neural server disclosure stays adjacent to provider selection.

**FIRST VIEWPORT:** At 360–420 px wide, title and connection state lead; an oversized circular play control interrupts a full-width progress rail; previous/next/stop sit on that same transport axis. The current sentence cue and exact progress follow before sticky controls, with provider details below the primary task.
